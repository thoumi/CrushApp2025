Linux

Fiche de synthèse par Lhoussaine Thoumi · Mise à jour le 3 août 2026

La base commune à Docker, Kubernetes et à quasiment tout serveur de production : permissions, processus, réseau et logs. Ce qu'un conteneur ou un cluster masque en surface finit toujours par redevenir un problème Linux au niveau du dessous.

Vue d'ensemble

« Tout est fichier » est la philosophie centrale d'Unix : périphériques, processus, sockets réseau sont exposés comme des fichiers, manipulables avec les mêmes outils. Une fois ce principe intégré, la plupart des commandes système deviennent prévisibles plutôt qu'à mémoriser une par une.

Concepts clés

Permissions (rwx, propriétaire/groupe/autres)
chmod 755 script.sh = propriétaire en lecture/écriture/exécution, groupe et autres en lecture/exécution seulement. Le chiffre encode les trois bits (4=read, 2=write, 1=execute) additionnés par catégorie.
Processus & signaux
Chaque processus a un PID et un parent. SIGTERM (15) demande un arrêt propre, SIGKILL (9) tue immédiatement sans laisser l'occasion de nettoyer, à utiliser en dernier recours.
systemd
Le gestionnaire de services de la majorité des distributions modernes : démarre, surveille et redémarre automatiquement les services déclarés en unit files.
Redirections & pipes
> écrase, >> ajoute, | chaîne la sortie d'une commande vers l'entrée de la suivante : la base de tout script de diagnostic.
Montages & systèmes de fichiers
Un disque n'existe pour les programmes qu'une fois monté sur un point de l'arborescence (/mnt, /media...), pas de lettre de lecteur comme sous Windows.

Scripting Bash

Un script bien écrit échoue bruyamment plutôt que silencieusement : set -euo pipefail est le premier réflexe avant d'écrire quoi que ce soit d'autre.

#!/usr/bin/env bash
set -euo pipefail   # stoppe au premier échec, variable non définie = erreur

ENV="${1:-staging}"           # valeur par défaut si aucun argument
LOG_DIR="/var/log/app"

if [[ ! -d "$LOG_DIR" ]]; then
  echo "Dossier de logs introuvable : $LOG_DIR" >&2
  exit 1
fi

for f in "$LOG_DIR"/*.log; do
  echo "Archivage de $f pour l'environnement $ENV"
  gzip "$f"
done

set -e arrête le script à la première commande en échec, -u transforme une variable non définie en erreur plutôt qu'en chaîne vide silencieuse, -o pipefail propage l'échec à travers un pipe. Sans ça, un pipe où seule la première commande échoue peut passer inaperçu.

Planifié via crontab -e (0 3 * * * /opt/scripts/archive-logs.sh production) pour une exécution récurrente, sans intervention manuelle.

Sécurité & pare-feu

ufw / iptables
ufw simplifie la configuration d'iptables sous-jacent : ufw allow 22/tcp puis ufw enable ferme par défaut tout ce qui n'est pas explicitement autorisé.
Durcissement SSH
Désactiver l'authentification par mot de passe (PasswordAuthentication no) au profit de clés, et interdire la connexion directe en root (PermitRootLogin no) dans /etc/ssh/sshd_config.
Gestion des paquets
apt (Debian/Ubuntu) ou dnf (RHEL/Fedora) installent et mettent à jour les paquets système ; des mises à jour de sécurité automatiques (unattended-upgrades) réduisent la fenêtre d'exposition aux CVE connues.
sudo ufw allow 22/tcp
sudo ufw allow 443/tcp
sudo ufw enable
sudo ufw status verbose

Cheat sheet

ps aux | grep nginx

kill -15 <pid>             # arrêt propre
df -h                      # espace disque
du -sh */                  # taille par dossier

# Réseau
ss -tulpn                  # ports en écoute (remplace netstat)
curl -I https://exemple.com
ping -c 4 exemple.com

# Fichiers & recherche
find . -name "*.log" -mtime -1
grep -R "ERROR" /var/log/
tail -f /var/log/syslog

# systemd
systemctl status nginx
systemctl restart nginx
journalctl -u nginx -f

Questions d'entretien fréquentes

Différence entre SIGTERM et SIGKILL ?

SIGTERM demande poliment au process de s'arrêter (il peut intercepter le signal et nettoyer avant). SIGKILL le tue immédiatement au niveau noyau, sans possibilité de nettoyage, à réserver aux process qui ne répondent plus.

Comment savoir quel process occupe un port ?

ss -tulpn | grep :PORT (ou l'historique netstat -tulpn), qui liste le PID et le nom du process en écoute.

À quoi sert chmod 755 ?

Donne au propriétaire les droits lecture/écriture/exécution (7), et au groupe comme aux autres uniquement lecture/exécution (5), typique pour un script exécutable partagé sans droit d'écriture externe.

À quoi sert set -euo pipefail en tête d'un script Bash ?

À faire échouer le script bruyamment plutôt que de continuer sur une erreur silencieuse : arrêt à la première commande en échec (-e), variable non définie traitée comme une erreur (-u), et échec propagé à travers un pipe (-o pipefail).

Comment sécuriser un accès SSH exposé sur Internet ?

Désactiver l'authentification par mot de passe au profit de clés, interdire la connexion root directe, et restreindre le port avec un pare-feu (ufw). L'attaque par force brute sur mot de passe reste le vecteur le plus courant sur un serveur mal configuré.
